# Problem Definition

The task is to simulate the reverse continuous-time Markov chain (CTMC) of a
discrete diffusion model and return samples whose distribution is as close as
possible to the data distribution, under a fixed budget of intensity (score)
evaluations.

## Setting

- State space `X = [S]^d` with `S = 15` states per site and `d = 48` sites.
- Forward process: every site is noised independently by the uniform-rate CTMC
  `Q = E / S - I` (the analytic model of the paper's toy experiment), run for
  horizon `T = 12`.  At time `T` the distribution is uniform up to a
  truncation error of order `e^{-T}`.
- Reverse process: the time-reversed CTMC from `p_T` (start from uniform
  samples) back to the data distribution `p_0`.  Its jump intensities are
  exact: there is no learned score, so all error comes from how the reverse
  process is simulated.
- Data distributions are synthetic multi-site distributions with several
  separated modes of unequal weight and unequal spread.  They are generated by
  the evaluators; the held-out ones are never visible.

## What a solver receives

A solver is a Python callable `solve(problem) -> np.ndarray` returning an
integer array of shape `(problem.num_samples, problem.num_sites)` with values
in `[0, num_states)`.  The `problem` object has:

| attribute | meaning |
|---|---|
| `num_samples`, `num_sites`, `num_states`, `horizon` | sizes and `T` |
| `nfe_budget` | number of intensity evaluations allowed per sample |
| `initial_states` | `(num_samples, num_sites)` uniform starting states (shared by every method) |
| `rng` | a seeded `numpy.random.Generator` (shared seed for every method) |
| `rates(states, s)` | exact reverse-process jump intensities |
| `nfe_used` | evaluations charged so far |

`rates(states, s)` takes an `(m, d)` integer array and a reverse time `s` in
`[0, T]` (a scalar, or one time per row) and returns an `(m, d, S)` array whose
entry `[j, i, y]` is the intensity of the single-site jump that sets site `i`
of row `j` to `y` (zero for the current value).  Reverse time `s` corresponds
to forward time `T - s`; `s = T` is the data end.  A request of `m` rows costs
`ceil(m / num_samples)` evaluations; requests are limited to `4 * num_samples`
rows.  Exceeding `nfe_budget`, asking for times outside `[0, T]`, invalid
states, exceptions, a time limit of 30 minutes per run, or returning samples of
the wrong shape or range all count as a failed run.

## Registering a solver

Any module under `method/` or `baseline/` that defines a top-level dict
`SOLVERS = {"name": callable, ...}` is discovered by the evaluators; every
registered name is scored as a separate method.  Solvers run in a separate
process and reach the instance only through `rates()`.  A registry that
cannot be imported, is empty, or whose solver fails on any instance or budget
receives the worst value of every scored metric.

Use `bash scripts/evaluate_train.sh` (optionally `--only NAME ...`) to score
registered solvers on the public train instances; it writes
`scoring/scores_train.json`.
